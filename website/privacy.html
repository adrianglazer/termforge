Scope & operator

This draft covers the Termforge iPhone app and this static support website. The app is an SSH/SFTP client, not a hosted server service. No Termforge account, proprietary backend, telemetry service, analytics integration, or cloud sync is configured in the reviewed source.

The operator's identity and contact details are pending. This is not a filed App Store privacy label or a blanket claim that no information leaves your phone. Commands, files, and authentication intentionally travel to the hosts you select.

Local app data

Local SQLite storage contains server names, hostnames, ports, usernames, connection preferences, known-host public keys and fingerprints, workspace layouts and pane titles, settings, snippets, and public key metadata with opaque credential references.

Connection history records the related server, start/end times, and outcome. It is distinct from terminal content: terminal transcripts and command history are not persisted. Active terminals still hold output in bounded memory. User-authored snippets or configuration text can contain sensitive information if you enter it.

The source applies iOS file protection to app-private metadata, sidecars, downloads, and staging files, and marks private data excluded from backup. Backup exclusion is system guidance, not a guarantee. No iCloud sync entitlement is configured. Current-candidate OS-level protection and lifecycle behavior still require physical acceptance.

Credentials & authentication

Private keys and supported stored credentials use app-scoped iOS Keychain items requiring a device passcode, with device-only, nonsynchronizing accessibility. Protected use requires device authentication. Password/passphrase entry and private-key import occur through native prompts and file handling; ordinary app metadata uses references rather than private key bytes.

Imported encrypted OpenSSH Ed25519 keys retain their encrypted representation and prompt for a passphrase on use. Remembering passphrases is currently unavailable. Generated Ed25519 keys use Keychain protection; they are not Secure Enclave keys and do not support generated-key passphrase encryption or private-key export.

SSH authentication communicates with the chosen server: password authentication sends the password inside the verified SSH transport; key authentication uses the key to authenticate. Private keys are not uploaded to a Termforge backend. Removing a passcode or restoring onto another device can make credentials unavailable. Swift and library memory copies prevent a perfect-memory-erasure guarantee.

Your remote servers

The app connects over SSH to the host and port you choose, including a configured supported bastion route. The destination receives your network address, authentication exchange, commands, and file operations. SFTP uploads send selected file contents; downloads receive remote content.

Server and network operators have their own logging, access, and retention policies. Your commands may write files or start processes on the server. Removing local app data or disconnecting does not erase server logs, reverse remote actions, or delete transferred files.

Host-key inspection and validation precede credential use in the implementation; an unexpected changed key blocks connection. Independently verify fingerprints. These mechanisms are not a certification or a guarantee against every threat.

Imports, exports & clipboard

File import/upload uses native, user-selected Files access with bounded temporary copies. Downloads and editor operations create protected temporary content; the source removes completed/discarded and stale staging files, with crash cleanup. Interrupted operations and file-provider behavior remain physical acceptance checks.

Configuration export uses an allowlist and excludes credential fields, key references, and trusted-host records. Snippet commands and other public metadata remain user-authored content; a scanner cannot guarantee they contain no manually entered secrets. Review every export before sharing.

Saving to Files, copying public keys or terminal selections, and explicit share actions can move data outside the app sandbox to a destination or file provider you choose. That provider and iOS clipboard/backup features have their own practices. Deleting the app cannot retrieve shared copies.

Diagnostics & support

Application diagnostics are restricted to allowlisted event/error codes and numeric operational context such as counts and timings. The production logging paths exclude raw server errors, hostnames, full paths, credentials, terminal output, clipboard contents, and file bodies; dependency logging is suppressed. No app-owned remote diagnostic uploader is configured.

Apple/iOS diagnostic handling depends on system settings and platform practices. This draft does not assert that operating-system diagnostics never exist or that every third-party component has received final release approval.

Retention, deletion & recovery

Saved metadata remains on the device until removed through the relevant app controls or app-data removal. Deleting a saved key closes dependent sessions and coordinates removal of its Keychain item and metadata through a recoverable deletion record. If the operation is interrupted, it is retried after unlock/startup.

Uninstalling an iOS app may leave Keychain items. The implementation prevents silent reuse after reinstallation and requires explicit reassociation or cleanup. New-device restoration or changed protection settings can make old credentials unusable. Keep original keys and reviewed configuration exports for recovery.

Background/idle lock initiates teardown of live sessions and temporary file authority. Temporary-copy cleanup is implemented; secure erasure of flash storage and perfect memory erasure are not promised. Copies on your servers, in Files providers, clipboard destinations, exports, or backups must be managed separately.

These components run in the client; their inclusion alone does not establish a separate hosted data service.

Apple handles app distribution and operating-system services under its practices. Chosen remote hosts, network providers, and Files providers may process your data. Final SDK/archive privacy declarations and dependency/notice review remain public-release requirements.

Website, hosting & cookies

This site serves local HTML, CSS, and brand images. It includes no JavaScript, analytics, advertising, cookies, browser storage, remote fonts, embedded third-party video, or contact form. Following an eventual App Store or contact link will take you to that destination's service.

A hosting provider may process IP addresses, requested paths, timestamps, browser details, and errors as part of serving and protecting the website. No production host is selected in this draft. The supplied local Docker server disables access logs; error logs may include request details. That configuration does not determine a future provider's logging.
