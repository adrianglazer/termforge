# Terminal engine

Decision: SwiftTerm **1.19.0**, UIKit `TerminalView`, behind the native terminal module. Research only; Expo integration, device behavior, and benchmarks are **not verified**.

## Selection and limits

SwiftTerm supplies a Swift terminal parser/model and UIKit frontend, with upstream terminal tests and fuzzing. Its selected manifest requires Swift tools 6.0, uses Swift 5 language mode, supports iOS 14+, and includes resources/build tooling that packaging must preserve. Recent releases show active rendering, input, memory, and accessibility work. Retain MIT notices, including inherited author notices. [Project](https://github.com/migueldeicaza/SwiftTerm), [selected release](https://github.com/migueldeicaza/SwiftTerm/releases/tag/v1.19.0), [manifest](https://raw.githubusercontent.com/migueldeicaza/SwiftTerm/v1.19.0/Package.swift), [license](https://raw.githubusercontent.com/migueldeicaza/SwiftTerm/v1.19.0/LICENSE).

Expo SDK 57 inline modules compile the Termforge native facade in the main iOS
target. `withTermforgeNativePackages` adds exact Swift Package Manager pins for
SwiftTerm 1.19.0 and Citadel 0.12.1 to that target, preserving SwiftTerm's
resources and build-tool plugin. A headless EAS worker cannot show Xcode's
one-time package-plugin trust prompt, so the EAS pre-build hook skips that
interactive fingerprint dialog. This exception is limited by the exact package
pins; changing either repository or version requires a source review and a new
device proof before rebuilding.

Alternative: xterm.js is mature, MIT-licensed, and supports terminal applications, Unicode, and accessibility. It would require a bundled WKWebView frontend and another input/data boundary. Prefer UIKit for this iOS-only product; revisit xterm.js only if the native proof fails. A custom emulator or React text-grid implementation would create excessive compatibility/performance work. [xterm.js](https://github.com/xtermjs/xterm.js).

The upstream package is evidence of feasibility, not proof of all Termforge requirements. Search indexing, configurable bounds, custom key toolbar, theme controls, safe OSC policy, and pane integration are adapter work unless the selected tag exposes suitable APIs. VoiceOver and IME behavior need physical-device testing. Do not assume a macOS Metal feature also works on UIKit.

## Data and rendering design

```text
remote PTY → Citadel byte stream → bounded native queue → SwiftTerm → UIKit
remote PTY ← Citadel writer ← terminal-generated bytes ← native input/toolbar
                                    ↑
                         JS sends control intents only
```

- Preserve raw bytes through SSH; let the emulator handle split UTF-8 sequences and terminal modes. No per-output JS event, base64 stream, React cell grid, or persisted terminal transcript.
- Retain the native model/view for a session across route changes; detached sessions continue parsing within bounds. One active attached renderer per session initially.
- Start with 10,000 scrollback lines; allow 1,000/5,000/10,000/50,000/100,000. Enforce both line and byte ceilings: initial targets 32 MiB retained terminal data per session, 128 MiB aggregate, excluding renderer overhead. Evict oldest scrollback first and report truncation. Profile and tune; these are budgets, not measurements.
- Limit queued transport data to 1 MiB/session initially; pause upstream reads at high watermark and resume after draining. If Citadel's chosen stream cannot propagate backpressure, fix/adapt the native stream before shipping. Never drop arbitrary terminal bytes to catch up. Close with `RESOURCE_LIMIT` if safe bounding cannot be maintained.
- Calculate rows/columns from measured font cells and content bounds; ignore zero-size transient layouts. Coalesce resize during dragging, deliver the final dimensions, and serialize PTY resize with session generation. Default `xterm-256color`.
- Native keyboard input owns terminal mode encoding, modifiers, hardware keys, IME composition, application cursor/keypad modes, and bracketed paste. The toolbar sends semantic keys, not a second competing encoder. User input is never replayed on reconnect.
- Search is literal by default, bounded/cancellable, with case toggle and next/previous results. Selection offsets must handle wrapped lines, wide cells, and eviction without retaining discarded buffers.
- Implement terminal palette/font/cursor preferences natively; coalesce harmless title/activity events. Remote titles remain untrusted labels and never replace saved server identities.

## Remote-output policy

Allow bounded title changes and terminal rendering sequences. Block OSC clipboard read/write (including OSC 52), automatic URL/file opening, downloads, and remote-triggered local commands. OSC hyperlinks may be displayed only as inert links; explicit tap permits validated HTTP(S) destinations. Disable image/graphics protocols initially to limit memory and parser exposure. Implement policy at parser hooks, not regex replacement of the SSH stream.

Paste uses native clipboard access only after user action; preserve bracketed-paste mode. Optional large/multiline confirmation shows the destination session. Clipboard sharing and screen-reader output are explicit user-facing disclosures, never diagnostics.
