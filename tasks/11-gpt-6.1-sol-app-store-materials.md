3. SFTP browsing and file transfer workflow.
4. Remote file editing, if verified in the release candidate.

6. Snippets, terminal controls, or themes, selecting the strongest verified workflow.

- First inspect available assets and runnable iOS tooling. Capture the real app through an available compatible simulator/device/build if possible; use sanitized demonstration hosts and files. Local preview/mock components are not evidence of native iPhone behavior.

- Verify the current required iPhone display set in [Apple's screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/). A 6.9-inch canvas of 1320 × 2868 portrait / 2868 × 1320 landscape is currently accepted; recheck before export. Supply the required set and supported-size derivatives only where appropriate. Do not create an iPad set for an iPhone-only app.
- Never include passwords, private keys, personal hostnames/IPs, personal files, notifications, or real account information. Use benign sample commands/content and owned or appropriately licensed assets/fonts.
- Produce a website/social sharing image and reusable feature graphics from the same visual system where useful, clearly separated from App Store upload assets.
