## Completion record — 2026-10-05

### Resolved defects

- Added generation and monotonic sequence metadata to every native event.
  Session consumers reject old generations, duplicate/out-of-order events, and
  invalid transitions. Concurrent close/background requests are idempotent and
  late native completion cannot resurrect a removed session.
- Native teardown now cancels connection, ordered-input, resize, forward, and
  transfer work; closes target/jump clients; removes completed native sessions;
  and closes failed jump clients before retry. Input writes are serialized and
  resize bursts coalesce to the latest dimensions every 50 ms.
- The session owns its SwiftTerm view/model while detached and hands that model
  to a replacement Expo view. Terminal rendering remains native; React receives
  only control/state/progress events. Remote OSC clipboard, link-open, and iTerm
  content callbacks cannot cause local side effects.
- SFTP cancellation is isolated by session plus operation ID, including two
  simultaneous transfers in one session. Session close cancels all owned
  operations. Download temporary files are protected/excluded from backup;
  Files export and upload URLs are containment checked after symlink resolution.
- SFTP action segments reject slash, NUL, empty, `.` and `..` values while
  preserving exact existing filenames. Editor replacement keeps a rollback
  backup instead of deleting the original first and returns the post-save
  fingerprint. Unknown native/server exceptions are reduced to fixed safe
  messages before entering transfer records/UI.
- Password form values are cleared after native connection handoff, decrypted
  key bytes are reset where Swift value semantics permit, forward failures no
  longer emit raw native exceptions, and native error names now use the stable
  architecture code set.
- Direct JS and native pins remain unchanged. License families and required
  acknowledgements are recorded in `docs/dependency-licenses.md`; the release
  archive notice check is assigned to task 08.

### Compact task 08 device-only workload

Use the same signed release candidate and one physical iPhone. First record
source revision/dirty-patch identity, EAS build ID and image, TestFlight build
number, iPhone model, iOS version, and available memory-instrument source.

1. Open a practical four-session split layout. In parallel, stream 100,000
   numbered Unicode/ANSI lines in one pane, run a rapid log stream in another,
   and interact briefly with vim, tmux, and htop in the remaining panes. Rotate
   once and drag split sizes. Record stream completion time, baseline/peak/end
   memory, dropped/stalled rendering if any, input echo latency by observation,
   resize responsiveness, and whether each session remains isolated.
2. During that workload, start two large same-session SFTP transfers, cancel
   only one, and let the other finish. Record sizes, elapsed times, SHA-256
   results, UI responsiveness, cancellation latency, and temporary-file cleanup.
3. Trigger one Control Center `inactive` interruption and one real
   background/foreground cycle. Confirm inactive does not disconnect,
   background returns honestly disconnected, stale events do not revive the
   session, no input is replayed, and reconnect does not storm.
4. Send direct/composed Unicode and one near-limit paste, confirm keyboard
   responsiveness, then send hostile OSC clipboard/link output and verify no
   clipboard mutation or automatic open occurs.

These checks are device-only because Linux tests cannot establish Swift
compilation, UIKit frame pacing/memory, iOS input delivery, security-scoped URL
